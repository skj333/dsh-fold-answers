# dsh-fold-answers

把 DSH 聊天窗里**不需要看的助手回答**和**轮次尾部的文件卡片**折起来，随时点开。纯显示层：不改会话日志、不改模型上下文、不发任何请求。

## 入口（都在动作条里）

助手回答下方那条「复制 / 赞 / 踩 / 分享 / 用量」的动作条里，多两个图标：

| 图标 | 作用 | 出现条件 |
|---|---|---|
| ↑ / ↓ | 折叠 / 展开本轮收尾回答 | 一直有 |
| 两层方块 | 折叠 / 展开本轮的文件卡片（「已编辑 N 个文件」） | 只在本轮确实有卡片时出现 |

折叠后回答收成 `已折叠 · <开头几十字>`，点这行展开。**已折叠的开关会带一层浅色底**（`--dsw-alias-interactive-bg-active`，无边框），一眼就能看出当前是不是折叠态；未折叠时是透明底。状态按会话存在浏览器 `localStorage`（前缀 `dsh-fold-answers:`，卡片用 `...:cards:`），刷新/重开仍在。

早期版本在每条回答右上角还挂过一个「折叠」文字按钮，现已移除：每轮的动作条都有同一个开关，两处重复且会漂在正文上。

## 实现要点

- 两个控件是 `<span role="button">`，不是 `<button>`：从元素层面就没有原生按钮外观，应用里写给 `button` 的规则也碰不到。
- 外观全部内联（尺寸 / 颜色 / 透明底），样式表只负责 hover 浮层：即使样式表失效，也不会出现方框。
- 折叠回答：给行加 `data-dsh-fold="1"`，样式表隐藏除 stub 外的直接子元素。
- 折叠卡片：`[data-turn-tail]` 里「含我们按钮的子元素」= 动作条，其余直接子元素打 `data-dsh-tail-hidden`，由样式表 `display:none !important` 收起。
- 样式表按 id **复用并覆写**（不是"存在就跳过"）：避免上一个实例留下的旧规则继续生效。
- 选择器常量有的带方括号（`ACTION`、`ROW`），有的不带（`STUB`、`HIDDEN`），CSS 里分别用 `${ACTION}` 和 `[${HIDDEN}]`——这里写错会静默失效，测试专门断言了渲染后的选择器文本。
- `MutationObserver` 负责虚拟滚动新挂载的行、重渲染后的补挂与状态重放；两个动作条按钮通过 `dsh-fold-answers:change` 事件互相同步。

## 测试

jsdom + 真实 react-dom，23 项断言：旧样式表被覆写、选择器文本正确（无 `[[` 双括号）、回答折叠/展开、stub 预览、卡片折叠/展开、动作条不受影响、`aria-pressed` 同步、键盘 Space/Enter 触发、行上不再有重复按钮、过程行不被注入。

## 局限

- 依赖聊天行的 DOM 约定（`data-chat-flow-kind`、`data-chat-node-key`、`data-turn-tail`）；官方改结构需同步。
- 只能折叠每轮的收尾回答；轮次中间的过渡回答不可折叠（那属于「工作步骤」，用显示设置里的折叠即可）。
- 中断轮次没有 `data-turn-tail`，其上不出现卡片折叠按钮。
- 只影响当前页面的显示，不影响导出与模型上下文。

## 卸载

```
plugin_manager remove_bundle target=dsh-fold-answers
```
